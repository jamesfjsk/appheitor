Arquivo autossuficiente para a IA que vai executar (Cursor ou outra). Leia inteiro antes de escrever qualquer linha. Pré-requisito: Etapa 0 concluída, revisada (`docs/etapas/REVISAO_ETAPA_0.md`) e commitada. Duração estimada: 2 semanas de trabalho de IA.

## 0. Contexto

Miner Missions é o app de rotina diária do Heitor (10 anos, fã de Minecraft e futebol, joga **só no PC**; não tem celular) que está virando um jogo. Stack: React 18 + TypeScript strict + Vite + Tailwind + Firebase (Auth/Firestore/Storage), só cliente, OpenAI chamada do navegador, em `C:/Users/Nobody/Downloads/Samsonite/appheitor`. O roteiro completo é `docs/MINER_MISSIONS_ROADMAP.md`: leia a seção "Lógica principal que nunca muda" (invariantes), "Modelo de dados alvo", "Economia", "Etapa 1", "Revisão v2" (transversais e acréscimos da Etapa 1) e "Protocolo". Este arquivo é a especificação executável dessa etapa e prevalece quando detalhar algo diferente do roteiro.

O que a Etapa 1 entrega: a **Vila** como tela inicial do Heitor: uma cena viva em canvas com o personagem dele (sprites gerados por IA), a base com construções que evoluem, NPCs, dia e noite; as missões de casa pagando gold, XP e materiais; Oficina (equipamentos e troca de materiais), Mercado (prêmios reais + Loja da Vila), Baú do Dia, primeiro acesso com criação do personagem, prova do dia como portão do jogo, painel do pai com a aba Vila, conta de teste, observabilidade e manual do pai. Sem andar pelo mapa (decisão do pai: a sensação de vila viva basta).

## 2. Modelo de dados

`village/{uid}` (novo). Parser `fromVillageDoc` tolerante a campos ausentes; nunca gravar `undefined` (copiar `stripUndefined` de `englishBaseService.ts`).
```ts
interface VillageDoc {
  userId: string; createdAt: string; updatedAt: string;          // ISO
  name: string;                    // "Vila do Heitor" por padrão
  characterName: string;           // escolhido no primeiro acesso
  onboardedAt: string | null;
  rare: { diamante: number; esmeralda: number };
  gear: { pickaxe: 0 | 1 | 2 | 3 | 4; helmet: 0 | 1; boots: 0 | 1; lamp: 0 | 1; cape: 0 | 1 };
  character: { skin: string; hair: string; shirt: string; pants: string; hat: string | null; cape: string | null; pet: string | null };  // ids do catálogo
  owned: string[];                 // cosméticos comprados (ids do catálogo)
  claimed: Record<string, string>; // chave -> ISO; chaves: daily:<date>, quiz8:<date>, streak:<n>:<inicio>, level:<n>, event:<id>:<ano>, challenge:<id>, season:<n>
  shield: { helmetWeek: string | null };   // Etapa 2
  fullDays: number; fullDaysStart: string | null;   // dias completos seguidos (avança em closeDay)
  records: Record<string, number>; // Etapa 2
  decor: string[];                 // Etapa 4
}
```
- `englishBase.materials` (madeira, pedra, ferro, redstone): as missões somam aqui. `taskCompletions.materialsEarned: Partial<Record<Material, number>>` (ausente = 0 em leituras antigas).
- `settings/village`: `{ shopEnabled: true, effectsEnabled: true, goldPriceMultiplier: 1, team: { name: '', color1: '#5b9b3a', color2: '#ffffff' } }`.
- `settings/economy`: `{ materialsPerTask: 1, dailyChestGold: [5, 15], rareEveryNDays: 3, gameGoldDailyCap: 35, redeemMinTasks: 5, taskDefaultXp: 10, taskDefaultGold: 5, periodStartHours: { afternoon: 12, evening: 18 }, periodGating: true, chestOpenHour: 18, minDueForChest: 3 }` (padrões em código; o painel edita; o app lê com padrão quando o doc não existe).
- `settings/modules`: `{ shop: true, effects: true, bank: false, interest: false, logic: false, lines: false, dilemmas: false, mineShift: false, football: false, chat: false, tts: true, aiGeneration: true, music: false }` com hook `useModules()`; nesta etapa só `shop`, `effects`, `tts` e `aiGeneration` têm comportamento (os outros ficam prontos para as etapas seguintes).
- `settings/pauseDays`: `{ dates: string[] }` (dias de folga marcados pelo pai): `closeDay` grava `paused: true`, sem penalidade nem bônus; `fullDays` não muda.
- `settings/testChild`: `{ uid: string | null }` (conta de teste; ver seção 9).
- `clientErrors/{id}`: `{ message, stack (<= 2 KB), uid, route, appVersion, createdAt }` (create por logado, read admin). `health/{uid}`: `{ lastCloseDay, lastQuizGenerated, lastPlanGenerated, lastChestDate, updatedAt }` (atualizado pelos serviços correspondentes).
- `GoldTransaction.source` ganha `'village_shop' | 'chest' | 'task_reversal' | 'level_gift'`; rótulos em `src/components/parent/GoldHistory.tsx`. `goldTransactions.metadata` em compras: `{ itemId, price, catalogVersion }`.
- Regras (`firestore.rules`): `village/{uid}` leitura/escrita pelo dono (`uid == request.auth.uid`) e admin; `settings/*` já cobre os novos docs (leitura logado, escrita admin) — conferir; `clientErrors` create por logado, read/delete admin; `health/{uid}` dono e admin. Índices: nenhum novo nesta etapa.

## 3. Catálogo e economia (`src/config/village.ts`, `src/types/village.ts`)

- `MATERIAL_BY_PERIOD = { morning: 'madeira', afternoon: 'pedra', evening: 'ferro' }`.
- Construções: continuam em `src/config/englishBase.ts` (custos 3/5/8 com ferro >= 1); acrescentar `buildingSprite(id, level)` → `/assets/village/buildings/<id>-<level>.png` com fallback para o ícone atual quando o arquivo do nível não existir, e placa de lote vazio (`/assets/village/buildings/placa.png`) no nível 0. Desbloqueio: Torre, Mesa e Campinho só com Fornalha e Baú >= 1 (já existe).
- Equipamentos (`GEAR`): picareta pedra 6 pedra + 2 madeira; ferro 8 ferro + 4 pedra; ouro 10 ferro + 6 redstone + 1 esmeralda; diamante 12 ferro + 8 redstone + 2 diamante; botas 5 madeira + 3 ferro; capacete 6 ferro + 3 pedra; lanterna 4 redstone + 2 ferro; capa 6 madeira + 4 redstone + 1 esmeralda. Efeitos desta etapa: picareta pedra +1 material na 1ª missão do dia; ferro +1 na 1ª missão de cada período; ouro idem + Baú do Dia com +1 material; diamante +1 em toda missão; botas +20% XP nas missões (arredondado); capacete, lanterna e capa só visuais aqui (efeitos na Etapa 2). Troca do Ferreiro: 3 materiais de um tipo por 1 de outro, sem gold.
- Cosméticos (`COSMETICS`, ids permanentes, `catalogVersion = 1`): peles (4) e 8 cores de camisa/calça grátis; penteados extras 3 x 20 gold; camisa do time 40 (usa `settings/village.team`); boné 30; capacete decorativo 60; capa vermelha 80, capa azul 120; pets lobo 120, gato 120, papagaio 150; coroa 200. Preço = `Math.round(base * goldPriceMultiplier)`. Itens premium (capa azul, coroa) marcados `premium: true`.
- Baú do Dia: abre só depois de `chestOpenHour` (18h), com todas as missões devidas concluídas e `due >= minDueForChest`; conteúdo determinístico por `hash(uid + date)` (xorshift de `src/services/english/shuffle.ts`): gold entre `dailyChestGold`, 2 materiais comuns, e 1 esmeralda quando `fullDays % rareEveryNDays === 0` (contando o dia atual); picareta de ouro/diamante +1 material. Gold do jogo no dia (baú + presente de nível) nunca passa de `gameGoldDailyCap`.
- Presente de nível: ao subir de nível, 1 material (madeira) e modal; chave `level:<n>` em `claimed`.
- Horários: `periodGating` (padrão ligado): missão da tarde só a partir das 12h e da noite a partir das 18h (hora do Brasil). A verificação vale na tela (botão desabilitado com "Abre às 12h") e no serviço (recusa com erro claro).

## 5. Serviços (Firebase)

`src/services/villageService.ts` (padrões: `subscribeBase`/`fromBaseDoc` em `englishBaseService.ts`; `runTransaction`; `stripUndefined`; datas ISO):
- `ensureVillage(uid)` (só quando `user.role === 'child'`; cria com `INITIAL_VILLAGE`), `subscribeVillage(uid, onChange, onError)`, `getVillage(uid)`.
- `completeOnboarding(uid, { characterName, villageName, character })`.
- `saveCharacter(uid, character)` (só peças grátis ou em `owned`).
- `buyCosmetic(uid, itemId)`: transação lendo `village`, `progress`, `settings/village`; recusa se já possui, se `shop` desligado ou se o saldo não cobre; grava `owned`, `availableGold`, `totalGoldSpent` e a linha `goldTransactions` (`type: 'spent'`, `source: 'village_shop'`, metadata); saldo nunca negativo.
- `craftGear(uid, gearId)`: transação lendo `village` e `englishBase`; valida custo (`canCraft`), debita materiais e raros, grava `gear`; recusa sem `effects` desligado? Não: crafting sempre permitido; só o efeito depende de `settings/village.effectsEnabled`.
- `tradeMaterials(uid, from, to)`: transação 3:1 em `englishBase.materials`.
- `openDailyChest(uid, date)`: transação lendo `village`, `progress`, `englishBase`, `tasks` e `taskCompletions` do dia (query fora da transação, resultado passado para dentro; a chave `daily:<date>` em `claimed` garante abertura única); valida horário, `due >= minDueForChest`, `done >= due`; grava `claimed`, materiais, raros, `availableGold`/`totalGoldEarned` e a linha `goldTransactions` (`type: 'earned'`, `source: 'chest'`, metadata `{ due, done, contents }`); atualiza `health.lastChestDate`. Devolve o conteúdo.
- `grantLevelGift(uid, level)`: chave `level:<n>`; +1 madeira; sem gold.
- `logClientError(err, route)` e `touchHealth(uid, field)` em `src/services/observability.ts` (instalar `window.onerror` e `unhandledrejection` em `src/main.tsx`; `__APP_VERSION__` definido em `vite.config.ts` via `define` com data + hash curto do git quando disponível).
- `src/services/settingsService.ts`: `subscribeSettings<T>(docId, defaults)` genérico para `village`, `economy`, `modules`, `pauseDays`, `testChild`; `saveSettings(docId, partial)` (admin).

`src/services/firestoreService.ts`:
- `completeTaskWithRewards(taskId, userId, xp, gold, loot?: { material: Material; qty: number })` vira `runTransaction`: lê `tasks/{taskId}` e recusa se `lastCompletedDate === today` (fecha o toque duplo); lê `englishBase/{uid}` e, se não existir, cria o doc inicial com `userId` (copiar `initialBaseDoc` de `englishBaseService.ts` ou expô-lo) e materiais; se existir, `increment`; grava `progress` (`increment`), `taskCompletions` (com `materialsEarned`), `goldTransactions` como hoje. Comportamento offline muda: sem rede a missão não conclui; `DataContext.completeTask` mostra "Sem internet: a missão não foi salva" e desfaz o otimista.
- `updateStreak` vira `runTransaction` (mesma regra).
- `revertTaskCompletion(taskId, date, adminUid)` (admin): transação que apaga/marca a `taskCompletions` do dia (`reverted: true`), devolve XP e gold (`source: 'task_reversal'`, negativo, saldo nunca abaixo de zero), devolve materiais, volta `tasks.status`/`lastCompletedDate`, e se o Baú do dia já foi aberto grava `village.claimed['daily:<date>']` como está (não reabre) mas registra `metadata.reverted`. Contagem em `health`/relatório fica para a Etapa 2.
- `src/contexts/DataContext.tsx` (`completeTask`): calcula `loot` com `computeTaskLoot` (lê `village` e `settings/economy` do contexto novo), aplica `xpWithBoots`, verifica `periodAllowedAt`, chama `completeTaskWithRewards(..., loot)`, toast "+5 gold, +1 madeira, +10 XP"; `checkLevelUp` chama `grantLevelGift` e abre o modal de nível; o gate de resgate passa a usar `dueTasksOn` e `settings/economy.redeemMinTasks`.
- `src/services/dailyRulesService.ts` (`closeDay`): usa `dueTasksOn`; lê `settings/pauseDays` (dia de folga = `paused: true`, sem penalidade/bônus) e, com punição ativa na data, grava `punished: true` sem penalidade/bônus; atualiza `village.fullDays`/`fullDaysStart` (`done >= due` avança; dia perdido zera; folga, férias e punição não mexem) e `health.lastCloseDay`. `dailyRules.enabled` passa a `true` por padrão com `penaltyPerMissedTask: 1` (padrão em código quando o doc não existe; o painel continua podendo desligar).
- `src/contexts/VillageContext.tsx`: assina `village`, `englishBase`, `settings/{village,economy,modules,pauseDays}`; expõe `village`, `materials`, `settings`, `modules`, ações acima com toasts; monta dentro de `DataProvider` só para `role === 'child'` (o painel do pai lê via serviços, não via contexto).
